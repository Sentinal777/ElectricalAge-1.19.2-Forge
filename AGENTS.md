# Various Notes

* This is a Minecraft Forge 1.7.10 mod called Electrical Age (Eln). It uses an updated GTNH Gradle build system.
* We are aiming to move to 100% Kotlin. Where possible, use Kotlin for new code.
* Java source files belong in the `src/main/java` directory. Kotlin source files belong in the `src/main/kotlin` directory.
* Do not update the Gradle configuration or wrapper without asking first. They are from an upstream repository.
* If you create documentation, please add it do the `docs` directory.
* Do not move the `id` or `subId` of existing registered items or blocks unless explicitly asked. Those values are world-save sensitive and changing unrelated ones breaks existing saves.
* **i18n (internationalization) workflow**:
  - Wrap all user-facing strings with `tr()` and item/block names with `TR_NAME()`.
  - Avoid dynamically constructing strings; keep them as complete phrases so translators can work with them.
  - Use positional parameters (`%1$`, `%2$`, …) for runtime values instead of string concatenation or direct variable embedding — this allows translators to reorder arguments for their language.
  - After adding new items or translatable strings, run `./gradlew generateLangFiles` to update the language files. Do not manually edit language files unless fixing an existing translation.
* The javac deprecation/unchecked warnings reported from `build/rfg/minecraft-src/java` were already investigated. They come from generated/decompiled patched Minecraft/Forge sources, not Electrical Age source. Running `compilePatchedMcJava` with `-Xlint:deprecation` and `-Xlint:unchecked` shows details such as deprecated Forge progress APIs and raw collection usage in Minecraft classes. There is not a meaningful durable fix in this repository because `build/rfg/minecraft-src` is generated from an external source; suppress, isolate, or leave diagnostic lint opt-in rather than trying to patch those generated files.

# Sandbox

* Windows native 1.19.2 development uses Java 17 and the wrapper inside `forge-1.19.2`, with a task-specific Gradle cache. The pinned native Forge target is exactly 43.5.0. Use explicit UTF-8 for Python generator reads/writes; Windows default cp1252 cannot encode some original item names.
* Build the normal release without `-PbcceIntegration` or `-PclientSmoke`; those switches add QA-only sources. `-PbcceIntegration` loads the published BCCE 8.0.23 artifact for real engine/pipe tests. The normal `-all.jar` embeds Kotlin and Commons Numbers but not BCCE.
* `-PclientSmoke` is an automated rendering check, not manual mouse/keyboard gameplay. The optional pacing agent in `qa/` works around this host's stalled GLFW event loop and is excluded from the normal mod. Do not include its classes or flags in production installations.
* Resource regeneration can overwrite migrated solver files. Keep the accumulation, source ownership and duplicate PowerSource callback fixes in `tools/migrate_core.py` as well as the generated Java sources. Inspect actual GameTest pass/failure lines, not only a Gradle success message.
* Native and BCCE GameTest runs use separate working directories (`run/gametest-native` and `run/gametest-bcce`). Reusing a test world between those profiles leaves absent BuildCraft registry entries, pipes, fluids and chunk tickets in the native run. Keep old test worlds as evidence; create isolated profile directories instead of deleting or modifying personal worlds.
* Lighting and lifecycle GameTests wait for actual ticking chunks and use a separate lighting batch. An invisible light block must have an empty selection shape and register previously empty high light sections; verify Minecraft block light values, not just the block emission property. Use `-PqaWorld=gametest-<profile>-<purpose>` for a fresh isolated diagnostic world while retaining previous evidence.
* Forge calls `Item.initializeClient` from the superclass constructor. Kotlin subclass fields such as a part definition are still null at that point; defer definition-dependent choices to the actual renderer callback. Headless tests will not expose this client-only startup path.
* Original electrical processes default to 20 Hz (`ConfigHandler.kt`), while the native solver uses ten numerical subdivisions by default. Normalize per-step mechanical drag to the original physical time; increasing solver precision must not multiply friction. Shaft device controllers remain physical energy consumers/producers.
* Start client device audio from the block-entity client ticker as well as rendering, so an operating machine outside the camera view still plays. Automated GUI tests must wait near the target before opening it; clear terrain around isolated model yards and inspect the screenshots themselves.
* On Windows, migration source selectors must use `Path.as_posix()` before matching `mods/eln/` or test-package prefixes. A successful migration must retain the reviewed solver fixes; the native unit suite checks their behavior.
* Preserve device sampling timers and filter state across circuit rebuilds. A topology change elsewhere in the dimension must not restart a wind obstruction scan or change a water turbine's sampling rate.
* Wind/water OBJ files use the normal transparent-node frame, while mechanical shaft meshes receive an additional ninety-degree rotation. Their ghost coordinates and ports must follow the appropriate frame. The fixed wind body uses native rotation 3; rotating its cable does not rotate its body.
* A physical shaft placement or rotation can trigger the original unsafe-merge failure. Its transient join flag must not be serialized or set during chunk loading. Item placement starts a separate shaft history; saved world histories reconnect without a false placement event.
* Use Forge's separate-transform model loader for original inventory sprites plus held 3D meshes. Normalize large held projections to their own bounding box. Preserve descriptors whose original inventory rendering was itself 3D.
* Client QA must inspect client block entities on the render thread and queue server block-entity work through `server.execute`; `ServerLevel.getBlockEntity` intentionally returns null from the wrong thread. Check finite energy ledgers on one authoritative server snapshot, because menu-slot packets and block-entity measurement packets can arrive at different times.
* Carrier light must be available through immutable block state, without a block-entity lookup by the lighting worker. Register the first emitter's high section and revisit its source after pending chunk-light work, as for projected light spots. Verify actual block light and its removal in a reused profile as well as the emission value.
* Projected lights revisit both their high section and column light enablement after pending chunk-light work. Tests may wait a bounded interval for actual brightness, then must verify actual expiry; an emission property alone is insufficient.
* Original passive components now use real hardware inventories. Use creative adjustable parts for arbitrary numerical test loads, and verify original hardware separately. Variable inductor field energy must survive controller changes and circuit rebuilds without increasing from an unpowered control.
* Fresh wireless transmitters/receivers have one original signal terminal. Rewire old test fixtures to that terminal instead of restoring the preview's four internally joined pins. Saved preview radios preserve their old terminals through explicit migration.
* `GameTestYards.clear(helper,height,below,above)` uses vertical offsets and clears horizontal coordinates 0 through 16. Keep ordinary sky fixtures inside that area or explicitly clear a larger isolated volume; the last two arguments are not horizontal bounds.
* Forge ticket level 32 can keep overhead blocks ticking while their minecart entities are asleep. Gate cart charging on `ServerLevel.isPositionEntityTicking`, preserve uncollected paid work when serializing, and clean contacts from `onRemovedFromWorld` as well as `remove`: chunk unloading may call final `setRemoved` directly. Guard contact callbacks by entity identity as well as UUID so an old unloaded cart cannot detach a new instance.
* Original signal bus cable geometry is generated from the original cable texture and dimensions; it intentionally has no OBJ model. Keep that concrete geometry case in the artwork validation. Power antenna weather fixtures must set rain/thunder strengths explicitly because Minecraft fades weather flags in over time.
* Five-tick projected-light leases must also expire in loaded full chunks without ordinary block-entity ticking. Maintain loaded light spots by actual block-entity identity on the server tick, remove registrations on unload, and never force a chunk for cleanup. Reused worlds retain chicks from earlier incubator tests; count newly spawned UUIDs when asserting one egg produces one baby.
* Vanilla ThreadedLevelLightEngine can leave a partial task batch pending until ServerChunkCache.MainThreadExecutor.pollTask reaches tryScheduleUpdate; distance-manager work returns before that call. Schedule pending lighting after the ELN server tick as well, so a busy reused profile does not strand even a vanilla torch's emission update. Verify real light, not only the engine's hasLightWork flag, which omits pending task batches.
* Original Fabricator recipe buttons must use `this.y` inside the anonymous Button renderer. An enclosing screen-initialization local named `y` otherwise captures the wrong position, leaving all recipe icons above their actual buttons; only screenshot review exposed it.
* Raised Auto Miner terminals use owned, ticking ghost cells and preserve the original cable resistance. A 30 kW nominal silk-touch load draws slightly less power at its actual terminal voltage; test the real V-squared/R equation rather than ideal source watts. The original AutoMiner OBJ has no `ledA3`; its renderer intentionally tolerates that absent group.
* Reused automated mining worlds can retain item entities from earlier fixtures. Distinguish newly dropped UUIDs when counting a removed machine's contained hardware and installed-pipe refunds. Keep exact physical counts and test stale inventory access after removal.
* Transporter names route across the entire loaded dimension. GameTests need per-fixture name prefixes, or a previous fixture's legitimate destination makes the next test correctly report an ambiguous name. A client player will normally pick up a nearby item entity; set the QA passenger item's pickup delay explicitly when testing separate player-plus-item transport cost and arrival.

* When `./gradlew` fails inside the sandbox claiming it “Could not determine a usable wildcard IP”, rerun with `GRADLE_USER_HOME=$PWD/.gradle` and, if needed, request escalation—the build otherwise succeeds once it can write its cache and bind to an IP.
* The experimental 1.19.2 adaptation is an independent project in `forge-1.19.2/`; run its own wrapper from that directory with Java 17. The upstream root build and wrapper remain unchanged. Native port status and known omissions are documented under that project's `docs/` directory.
* ForgeGradle needs Java HTTP/HTTPS proxy properties in environments where only proxy-mediated downloads work. Translate the configured proxy into JVM properties without printing credentials. Use a task-specific `GRADLE_USER_HOME`; do not reuse or clear another task's cache. The final source archive intentionally excludes local caches and runtime worlds.
* Kotlin and non-mod numerical dependencies need `minecraftLibrary` for development runs and Forge Jar-in-Jar for the installable artifact. Keep the Kotlin library non-transitive to avoid an annotation-module split-package conflict. Reobfuscate the Jar-in-Jar task explicitly; only the `-all.jar` is the complete runtime artifact.
* After populating the cache, `runGameTestServer --offline -x downloadAssets` avoids an unnecessary client-asset download for a headless test. Inspect GameTest results and loader logs as well as the Gradle exit status; a Minecraft loader crash can otherwise look like a successful run task.
* Sandbox execution cells may have separate network namespaces. Launch a virtual display, its authenticated X client and the Minecraft client from the same controlling process. Communicate with that process through scratch files instead of expecting another cell to reach its localhost port.
* Solar world-adapter tests need actual exposure to the sky. A GameTest template can be generated below an ocean; clearing a one-block column permits water to flow back in. The native solar test constructs its circuit above the terrain.
* Adding GameTests can move template positions within a reused profile. Old loaded assemblies then legitimately retain globally addressed Modbus unit IDs or source festive-light channels. Use a fresh `-PqaWorld` for a final suite after changing its case count and preserve previous worlds as evidence; dedicated lifecycle tests still exercise actual save/reload. The inspected reused control profile contained two saved unit201 stations, with the older one registered and the new one rejected as designed.
