# Electrical Age for Forge 1.19.2 — experimental partial port

This is a working native 1.19.2 adaptation of a subset of the supplied Electrical Age source. **It is not a complete port of Electrical Age, and it is not compatible with 1.7.10 worlds.** Preserved source files, assets, item names, and numeric legacy-ID metadata do not imply implemented features.

The original project remains at the archive root. The new build is isolated in `forge-1.19.2/`; the original Gradle configuration and wrapper were not changed. Build and install instructions are in `docs/GETTING_STARTED.md` in that directory.

## Implemented native systems

| Area | Implemented behavior | Limits compared with the original |
|---|---|---|
| Electrical simulation | Original modified nodal analysis solver, electrical loads, resistors, capacitors, inductors, sources and expression mathematics; 200 simulation steps per simulated second | One simulation manager per loaded dimension; no large-network performance benchmark |
| Placement and connections | Six components per carrier block, all six mounting faces, rotation, flat and corner connections, support removal and item drops | Original model envelopes, selection by aimed part, mounting-plane cable extension and overlap checks; full legacy multipart covers/ghost blocks are absent |
| Cables | Nine electrical cable variants, conductor resistance, temperature rise and thermal burn-out | Voltage tiers are metadata, not separate connection classes; no bundled/six-conductor cables, cover system, insulation or grid poles |
| Passive and control components | Resistors, rheostats, capacitors, inductors, switches, 12 breaker ratings, relays, idealized diodes and transformer components | Diode and transformer behavior is simplified; original winding, core and component inventory mechanics are absent |
| Batteries | Seven variants using the original voltage/charge curve, capacity calibration, discharge/recharge, single-use behavior, aging and saved charge/life | Simplified thermal coupling; protective shutoff replaces the original destructive failure path |
| Solar | Fixed and tracking small panels using the original nonlinear power process, floating terminals, sunlight direction and weather/opacity sampling | Tracking is always available on the tracking variant; original tracking-item mechanics are absent; the original panel mesh now animates within its 45-degree stops |
| Logic | All 12 extracted original logic functions, including PAL, Schmitt trigger, oscillator, D and JK flip-flops; persisted state and up to three inputs | Output stage is an ideal 5 V source with resistance, not the original current-limited output circuit |
| Analog | Nine original functions: op-amp, PID, sawtooth/sine oscillator, amplifier, voltage-controlled amplifier, summing unit, sample-and-hold and low-pass filter | Relevant gain/filter/PID/summing controls; output is limited to 0–5 V and original circuit-stage details are absent |
| Signal and sensing | Signal sources/trimmer/switch/button; redstone conversion; light, daylight and weather sensors; expression processor | Direct switch/button interaction and relevant settings; no complete original probe placement system |
| Wireless | Channel-based voltage transmission among loaded devices | Fixed 64-block range, same dimension only, no original range upgrades or full wireless simulation |
| Measurement | Multimeter, thermometer, live voltage/current/temperature in device screens, accumulated absolute energy; a bounded 120-sample logger history saved in NBT | Original analog needle, LED indicators, four-digit display atlas and logger screen trace; digital display currently uses its original default 0–1000 range for a 0–5 V signal; no range/dye/dot controls, export or mechanical energy-wheel animation |
| Thermal | Basic thermal cable and connected temperature probes; resistor/battery heat and ambient cooling | Not the original room/air/fluid/thermal network simulation |
| Machines | Electric furnace using vanilla smelting recipes; 48 V/240 V macerators, compressors and plate machines using native datapack recipes | Simplified power and processing model; original upgrade slots, heating-element mechanics, sounds and recipe progression are absent; rollers/compressor movement and progress now follow processing state |
| Other | One powered lamp; electrical-to-Forge-Energy converter with extraction capability; machine inventory automation | Lamp has a built-in light source, without bulb variants; converter uses a port-specific 1 joule = 1 FE scale and is extraction-only |
| Persistence/networking | Versioned component NBT, battery/logic/analog/equation state, capacitor voltage and inductor current across network rebuilds, block-entity updates and server-validated menu configuration | No old-world converter; capacitors and inductors discharge when picked up; logger history is not restored after pickup |
| Rendering/resources | Original OBJ/MTL coordinates, material textures, UVs, vertex normals, reviewed group selection, pivot metadata, original item icons and container artwork; 780 original PNGs are byte-identical | Original animation/interaction coverage remains partial; held items still use flat icons; copied sounds are not equivalent to implemented sound playback |

There are **111 registered component variants, 23 materials and three tools (137 items total)**. Variants often share one implementation; this is not 111 independent original machines. `docs/native-content.json` is the exact native registry and parameter list.

## Major systems still to port

- Mechanical power networks, shafts, clutches, turbines, engines and generators beyond the implemented electrical/solar sources.
- Fluid handling, tanks, pipes, combustion/fuel systems and the complete thermal simulation.
- Electrical grid cables, poles, power distribution, bundled conductors and the full connector/cover system.
- World generation, ore deposits, structures and the original survival progression and recipe balance.
- Most advanced machines, miners, automation devices, entities/turrets, vehicles, armor and specialized tools.
- Remaining original GUIs, animations, upgrade/bulb/component inventories and interaction details.
- ComputerCraft/OpenComputers, IC2 and other mod integrations, MQTT/Modbus and external interfaces.
- A migration tool for legacy 1.7.10 saves and registries, production-scale performance work and broad multiplayer/modpack compatibility testing.

The entire original source and resource tree is included so these systems can be migrated without recovering missing upstream files. `docs/source-inventory.json` enumerates the original source files and whether a counterpart exists at the same native path; that field is an inventory aid, not a completeness score. `literal-registrations.json` covers statically discoverable registration calls and is not an exhaustive registry dump.

## 0.2.0 visual and placement pass

The complete changes and compatibility notes are in `docs/CHANGELOG-0.2.0.md`. The native registry remains at 137 items. Existing 0.1.0 component saves retain their pin-direction convention; new placements use a right-handed frame on every face. This does not add legacy 1.7.10 world compatibility.

## Numerical fixes made during this port

Two changes go beyond Minecraft API adaptation. `SubSystem.addToI` now adds current contributions instead of overwriting them: multiple sources and capacitor history terms must coexist in the nodal right-hand side. `CurrentSource` now retains and clears its subsystem ownership correctly when attached/removed. Regression tests exercise parallel sources, source removal, capacitor charging and original series-solar behavior. These edits are recorded in the reproducible migration script.

Stateful gate inputs are restored when rebuilding a circuit to avoid synthetic clock edges and lost samples. Node block shapes are dynamic because their geometry depends on the block entity. The OBJ reader ignores two-vertex exporter guide edges instead of treating them as polygons.

## Scope of verification

See `docs/VALIDATION.md` for the actual checks and results for this build. Passing tests establish those cases only; they do not establish full parity with the original mod. Audio, broad mod compatibility, complete survival balance and large multiplayer networks have not been verified.
